# 2026 한우물제 안내 웹앱

금정중학교 한우물제(10월 28일, 서울랜드 이벤트홀) 식순·관람 안전·서울랜드 지도·자유시간/귀가·비상 연락 안내 사이트입니다.

## 접속 안정성 설계 (350명 이상 동시 접속 대비)

| 구분 | 방식 | 효과 |
|---|---|---|
| 학생 화면 | `index.html`, `data.json`, 이미지, 글꼴 모두 **버셀 CDN의 정적 파일** | 서버 프로그램이 돌지 않아 동시 접속자 수에 영향이 거의 없음 |
| 외부 의존 | 구글 폰트·외부 스크립트 **없음**, 글꼴도 휴대폰 기본 글꼴만 사용 | 다른 서버가 느려도 화면이 막히지 않고, 첫 화면이 바로 뜸 (전송량 약 19KB) |
| 오프라인 | 서비스 워커가 한 번 연 화면·식순·지도를 휴대폰에 저장 | 행사장에서 통신이 몰리거나 끊겨도 안내가 열림. 저장본을 보여 줄 때는 "오프라인 · 저장된 안내"로 표시 |
| 지도 보관 | 지도(약 1MB)는 따로 보관해 화면 코드 업데이트 때 다시 받지 않음 | 수정 배포 때마다 350명이 1MB씩 다시 받는 일을 막음 |
| 첫 화면 | 기본 식순이 `index.html` 안에 들어 있음 | `data.json`을 못 받아도 바로 표시 |
| 새 내용 확인 | 3분 ± 랜덤 간격, 같은 내용이면 304(빈 응답) | 350명이 같은 순간에 요청하지 않음 |
| 공지 확인 | 공지만 담은 아주 작은 `announce.json`(공지가 없을 때 약 60바이트)을 1분 ± 랜덤 간격으로 확인, 같은 내용이면 304(빈 응답). 화면이 꺼져 있으면 건너뜀 | 350명이 확인해도 버셀 CDN이 처리해서 서버 부담이 거의 없고, 공지가 1~2분 안에 뜸 |
| 선생님 저장 | 저장·공지 보내기 때만 `api/save` 실행 → 깃허브 파일 수정 → 버셀 자동 배포 | 저장 기능이 학생 접속에 영향을 주지 않음, 수정 이력이 깃허브에 남음 |
| 오류 대비 | 데이터가 잘못되면 기본 안내로 되돌림 | 흰 화면으로 멈추지 않음 |

## 폴더 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 웹앱 본체 |
| `data.json` | 현재 식순·안내 (선생님 수정 시 자동으로 바뀜) |
| `announce.json` | 지금 띄운 공지 (선생님이 "공지 보내기"를 누르면 자동으로 바뀜. 직접 고칠 필요 없음) |
| `api/save.js` | 비밀번호 확인 후 `data.json`·`announce.json` 저장 (버셀 서버 함수) |
| `sw.js` | 오프라인 저장 |
| `vercel.json` | 캐시 설정 |
| `emblem.png`, `icon-192.png`, `icon-512.png`, `manifest.webmanifest` | 교표, 홈 화면 아이콘 |
| `map.jpg` | 위치 표시용 서울랜드 지도 (`서울랜드 가이드맵.pdf`에서 뽑은 2440×1732 이미지, 982KB) |

디자인은 `instagram-light.md`(인스타그램 스타일 가이드)를 따릅니다. `fonts/` 폴더는 더 이상 쓰지 않아 지워도 됩니다.

## 1단계. 지도 이미지 (완료)

`map.jpg`는 `서울랜드 가이드맵.pdf`에 들어 있는 원본 이미지를 그대로 뽑아 만들었습니다. 휴대폰에 저장돼 오프라인에서도 보입니다.
이벤트홀·정문(집결)·의무실·안내소 위치는 미리 찍어 두었고, 선생님 대기 위치는 수정 화면에서 찍으면 됩니다.

지도를 다른 이미지로 바꾸면: `index.html`의 `MAP_W`, `MAP_H`를 새 이미지 크기로 고치고, 수정 화면에서 위치를 다시 찍고, `sw.js`의 `MAP_CACHE` 숫자를 올려 주세요.
`서울랜드 가이드맵.pdf`는 사이트에서 쓰지 않으니 깃허브에 올리지 않아도 됩니다.

## 2단계. 깃허브에 올리기

1. 깃허브에서 새 저장소를 만듭니다. (예: `hanumul`)
2. 이 폴더의 파일과 폴더(`api`, `fonts` 포함)를 모두 올립니다.

## 3단계. 버셀 배포

1. vercel.com → **Add New → Project** → 저장소 **Import**
2. Framework Preset: **Other**, 빌드 설정은 비워 둔 채 **Deploy**
3. 나온 주소(`https://….vercel.app`)가 학생용 주소입니다.

## 4단계. 수정 기능 켜기 (비밀번호)

### 깃허브 토큰 만들기
1. 깃허브 → 오른쪽 위 프로필 → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
2. Expiration: 행사 이후 날짜(예: 11월 말)
3. Repository access: **Only select repositories** → 이 저장소만 선택
4. Permissions → Repository permissions → **Contents: Read and write**
5. 만들어진 토큰을 복사합니다. (다시 볼 수 없으니 바로 다음 단계에 붙여 넣기)

### 버셀 환경 변수
버셀 프로젝트 → **Settings → Environment Variables**에 추가:

| 이름 | 값 |
|---|---|
| `ADMIN_PASSWORD` | 수정용 비밀번호 |
| `GITHUB_TOKEN` | 위에서 만든 토큰 |
| `GITHUB_REPO` | `깃허브아이디/저장소이름` |
| `GITHUB_BRANCH` | (선택) 기본 브랜치가 `main`이 아니면 입력 |

추가한 뒤 **Deployments → 최신 배포 ⋯ → Redeploy** 해야 적용됩니다.

비밀번호와 토큰은 버셀 서버에만 있고 `index.html`에는 없어서, 저장소가 공개여도 드러나지 않습니다.

## 사용 방법

- 맨 아래 **선생님 수정** → 비밀번호 → 식순·시간·집결 장소·지도 위치·안내 문구·연락처 수정 → **저장**
- 저장하면 깃허브 `data.json`이 바뀌고 버셀이 약 1분 안에 새로 배포합니다. 학생 화면은 그 뒤 3분 안에(또는 앱을 다시 열 때) 바뀝니다.
- 지도 위치: 수정 화면 **지도 위치 표시**에서 "지도에서 위치 찍기"를 누르고 지도에서 장소를 누릅니다. 5번 "선생님 대기 위치"도 같은 방법으로 찍습니다.
- 비상 연락처: 수정 화면 **비상 연락처**에서 역할·이름·전화번호를 고치거나 추가·삭제하고 **저장**합니다. (전화번호는 저장소가 공개면 누구나 볼 수 있어요.)
- **공지 띄우기**: 선생님 수정 화면 맨 위 "학생 화면에 공지 띄우기"에서 문구를 고르거나 적고, 띄워 둘 시간(5·10·30분)을 정한 뒤 **공지 보내기**. 저장 버튼과 상관없이 바로 보내지며, 학생 화면에는 1~2분 안에 큰 글씨로 뜹니다. 학생이 화면을 누르면 닫히고, 같은 공지는 다시 뜨지 않습니다(닫은 뒤에도 위쪽에 작은 띠로 남아요). **공지 내리기**로 바로 거둘 수 있고, 정한 시간이 지나면 저절로 사라집니다.
- 공지는 서울랜드에서 통신이 몰리면 늦게 뜰 수 있으니, 급한 안내는 인솔 교사가 직접 전달하는 것을 함께 쓰세요.

## 행사 전 꼭 할 일

1. **지도 탭에서 핀 위치 확인하기.** 집결 장소가 정문이 아니면 수정 화면에서 2번 위치를 다시 찍어 주세요.
2. **출발 전에 학생들이 한 번씩 접속하게 하기** (학교 와이파이나 버스 안). 서비스 워커가 화면과 지도를 저장해 두면 행사장에서 통신이 몰려도 열립니다. "홈 화면에 추가"를 안내하면 앱처럼 바로 열 수 있습니다.
3. 행사 당일 아침 이후 큰 수정을 하면 학생 휴대폰에 반영되는 데 몇 분 걸립니다. 식순 변경은 가능하면 전날까지 마쳐 주세요.

## 개발자 메모

- 화면 코드를 바꿔 다시 배포할 때는 `sw.js`의 `VERSION` 숫자를 올려 주세요. (데이터만 바꿀 때는 필요 없음)
- 연락처 등 `data.json` 내용은 누구나 볼 수 있습니다. 개인 휴대폰 번호 공개 여부는 학교 방침에 맞춰 정해 주세요.
