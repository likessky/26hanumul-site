# 2026 한우물제 안내 웹앱

금정중학교 한우물제(10월 28일, 서울랜드 이벤트홀) 식순·관람 안전·서울랜드 지도·자유시간/귀가·비상 연락 안내 사이트입니다.

## 접속 안정성 설계 (350명 이상 동시 접속 대비)

| 구분 | 방식 | 효과 |
|---|---|---|
| 학생 화면 | `index.html`, `data.json`, 이미지, 글꼴 모두 **버셀 CDN의 정적 파일** | 서버 프로그램이 돌지 않아 동시 접속자 수에 영향이 거의 없음 |
| 외부 의존 | 구글 폰트·외부 스크립트 **없음**, 글꼴도 휴대폰 기본 글꼴만 사용 | 다른 서버가 느려도 화면이 막히지 않고, 첫 화면이 바로 뜸 (전송량 약 19KB) |
| 오프라인 | 서비스 워커가 한 번 연 화면·식순·지도를 휴대폰에 저장 | 행사장에서 통신이 몰리거나 끊겨도 안내가 열림. 저장본을 보여 줄 때는 "오프라인 · 저장된 안내"로 표시 |
| 지도 보관 | 지도(약 1MB)는 따로 보관해 화면 코드 업데이트 때 다시 받지 않음 | 수정 배포 때마다 350명이 1MB씩 다시 받는 일을 막음 |
| 첫 화면 | 기본 식순이 `index.html` 안에 들어 있음 | `data.json`을 못 받아도 바로 표시 |
| 새 내용 확인 | 3분 ± 랜덤 간격, 같은 내용이면 304(빈 응답) | 350명이 같은 순간에 요청하지 않음 |
| 공지 확인 | 공지만 담은 아주 작은 `announce.json`(공지가 없을 때 약 60바이트)을 1분 ± 랜덤 간격으로 확인, 같은 내용이면 304(빈 응답). 화면이 꺼져 있으면 건너뜀 | 350명이 확인해도 버셀 CDN이 처리해서 서버 부담이 거의 없고, 공지가 1~2분 안에 뜸 |
| 선생님 저장 | 저장·공지 보내기 때만 `api/save` 실행 → 깃허브 파일 수정 → 버셀 자동 배포 | 저장 기능이 학생 접속에 영향을 주지 않음, 수정 이력이 깃허브에 남음 |
| 오류 대비 | 데이터가 잘못되면 기본 안내로 되돌림 | 흰 화면으로 멈추지 않음 |

## 폴더 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 웹앱 본체 |
| `data.json` | 현재 식순·안내 (선생님 수정 시 자동으로 바뀜) |
| `announce.json` | 지금 띄운 공지 (선생님이 "공지 보내기"를 누르면 자동으로 바뀜. 직접 고칠 필요 없음) |
| `api/save.js` | 비밀번호 확인 후 `data.json`·`announce.json` 저장 (버셀 서버 함수) |
| `api/quiz.js` | 퀴즈 문제 제공·답안 접수·채점·순위 (버셀 서버 함수 + Upstash Redis) |
| `tools/quiz-loadtest.js` | 퀴즈 부하 테스트 (배포되지 않음) |
| `sw.js` | 오프라인 저장 |
| `vercel.json` | 캐시 설정 |
| `emblem.png`, `icon-192.png`, `icon-512.png`, `manifest.webmanifest` | 교표, 홈 화면 아이콘 |
| `map.jpg` | 위치 표시용 서울랜드 지도 (`서울랜드 가이드맵.pdf`에서 뽑은 2440×1732 이미지, 982KB) |

디자인은 `instagram-light.md`(인스타그램 스타일 가이드)를 따릅니다. `fonts/` 폴더는 더 이상 쓰지 않아 지워도 됩니다.

## 1단계. 지도 이미지 (완료)

`map.jpg`는 `서울랜드 가이드맵.pdf`에 들어 있는 원본 이미지를 그대로 뽑아 만들었습니다. 휴대폰에 저장돼 오프라인에서도 보입니다.
이벤트홀·정문(집결)·의무실·안내소 위치는 미리 찍어 두었고, 선생님 대기 위치는 수정 화면에서 찍으면 됩니다.

지도를 다른 이미지로 바꾸면: `index.html`의 `MAP_W`, `MAP_H`를 새 이미지 크기로 고치고, 수정 화면에서 위치를 다시 찍고, `sw.js`의 `MAP_CACHE` 숫자를 올려 주세요.
`서울랜드 가이드맵.pdf`는 사이트에서 쓰지 않으니 깃허브에 올리지 않아도 됩니다.

## 2단계. 깃허브에 올리기

1. 깃허브에서 새 저장소를 만듭니다. (예: `hanumul`)
2. 이 폴더의 파일과 폴더(`api`, `fonts` 포함)를 모두 올립니다.

## 3단계. 버셀 배포

1. vercel.com → **Add New → Project** → 저장소 **Import**
2. Framework Preset: **Other**, 빌드 설정은 비워 둔 채 **Deploy**
3. 나온 주소(`https://….vercel.app`)가 학생용 주소입니다.

## 4단계. 수정 기능 켜기 (비밀번호)

### 깃허브 토큰 만들기
1. 깃허브 → 오른쪽 위 프로필 → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
2. Expiration: 행사 이후 날짜(예: 11월 말)
3. Repository access: **Only select repositories** → 이 저장소만 선택
4. Permissions → Repository permissions → **Contents: Read and write**
5. 만들어진 토큰을 복사합니다. (다시 볼 수 없으니 바로 다음 단계에 붙여 넣기)

### 버셀 환경 변수
버셀 프로젝트 → **Settings → Environment Variables**에 추가:

| 이름 | 값 |
|---|---|
| `ADMIN_PASSWORD` | 수정용 비밀번호 |
| `GITHUB_TOKEN` | 위에서 만든 토큰 |
| `GITHUB_REPO` | `깃허브아이디/저장소이름` |
| `GITHUB_BRANCH` | (선택) 기본 브랜치가 `main`이 아니면 입력 |

추가한 뒤 **Deployments → 최신 배포 ⋯ → Redeploy** 해야 적용됩니다.

비밀번호와 토큰은 버셀 서버에만 있고 `index.html`에는 없어서, 저장소가 공개여도 드러나지 않습니다.

## 사용 방법

- 맨 아래 **선생님 수정** → 비밀번호 → 식순·시간·집결 장소·지도 위치·안내 문구·연락처 수정 → **저장**
- 저장하면 깃허브 `data.json`이 바뀌고 버셀이 약 1분 안에 새로 배포합니다. 학생 화면은 그 뒤 3분 안에(또는 앱을 다시 열 때) 바뀝니다.
- 지도 위치: 수정 화면 **지도 위치 표시**에서 "지도에서 위치 찍기"를 누르고 지도에서 장소를 누릅니다. 5번 "선생님 대기 위치"도 같은 방법으로 찍습니다.
- 비상 연락처: 수정 화면 **비상 연락처**에서 역할·이름·전화번호를 고치거나 추가·삭제하고 **저장**합니다. (전화번호는 저장소가 공개면 누구나 볼 수 있어요.)
- **공지 띄우기**: 선생님 수정 화면 맨 위 "학생 화면에 공지 띄우기"에서 문구를 고르거나 적고, 띄워 둘 시간(5·10·30분)을 정한 뒤 **공지 보내기**. 저장 버튼과 상관없이 바로 보내지며, 학생 화면에는 1~2분 안에 큰 글씨로 뜹니다. 학생이 화면을 누르면 닫히고, 같은 공지는 다시 뜨지 않습니다(닫은 뒤에도 위쪽에 작은 띠로 남아요). **공지 내리기**로 바로 거둘 수 있고, 정한 시간이 지나면 저절로 사라집니다.
- 공지는 서울랜드에서 통신이 몰리면 늦게 뜰 수 있으니, 급한 안내는 인솔 교사가 직접 전달하는 것을 함께 쓰세요.

## 퀴즈 (객관식·단답형, 점수 + 빠르기 순위)

### 처음 한 번 설정
1. 버셀 프로젝트 → **Storage → Create Database → Upstash for Redis** (지역: 도쿄 `ap-northeast-1` 권장, 무료 플랜) → 이 프로젝트에 **Connect**. `KV_REST_API_URL`, `KV_REST_API_TOKEN`이 자동으로 들어갑니다. (`ADMIN_PASSWORD`는 위에서 넣은 것을 그대로 씁니다.)
2. **Deployments → Redeploy** 해야 적용됩니다.
3. 학번 형식이 5자리 숫자(예: 10203 = 1학년 2반 3번)가 아니면 `index.html`과 `api/quiz.js`의 `SID_RE`를 같이 고쳐 주세요.

### 진행 방법 (선생님 수정 화면 맨 위 "퀴즈" 카드, "저장"과 상관없이 바로 반영)
1. **문제 만들기**: 문제 추가 → 객관식(보기 2~5개, 정답 선택) 또는 단답형(인정하는 답을 쉼표로 여러 개) → 글·그림(선택) → **퀴즈 저장**. 글과 그림을 비우면 학생 휴대폰에는 번호와 답안칸만 나와서, 문제를 큰 화면으로만 보여 줄 때 쓰면 됩니다.
2. **새 회차 만들고 대기 열기**: 학생 퀴즈 탭에 학번·이름 입력칸이 열립니다. (미리 입력해 두면 시작할 때 타자 시간이 순위에 섞이지 않아요)
3. **▶ 시작**: 학생 휴대폰에 **10초 카운트다운**이 뜨고, 0초에 모든 휴대폰에서 **동시에** 문제가 열려요(서버가 그 시각 전에는 문제를 절대 내주지 않아요. 휴대폰 사이 차이는 1초 안팎). 큰 화면에서도 같이 10초를 세어 주세요. 순위의 "걸린 시간"은 **문제 공개 시각부터 서버가 제출을 받은 순간까지**이고, 관리 화면에 공개 시각이 표시돼요.
4. **■ 마감**: 마감 뒤 2분까지는 통신이 약해 늦게 도착한 제출도 받아요.
5. **결과 공개**: 학생 화면에 점수·정답이 나와요(학생 휴대폰이 직접 채점해 보여 주므로 서버 부담 없음). 순위표는 **결과 불러오기**, 전체는 **CSV 내려받기**.
6. 학번당 **첫 제출만** 인정해요. 같은 학번으로 다시 내려던 기록은 결과에 따로 표시돼요.
7. 시상할 때는 순위표의 학번·이름과 학생 휴대폰의 **접수 번호 화면**을 함께 확인해 주세요.

### 트래픽이 몰릴 때를 대비한 설계
| 구간 | 방식 |
|---|---|
| 문제·상태 받기 (3중 방어) | ① 버셀 CDN이 2초 캐시 (학생 요청은 일반 요청으로 보내 CDN이 받기 쉽게) ② CDN이 안 먹어도 서버 함수가 1초 동안 기억해서 Redis에는 인스턴스당 1초에 1번만 물어봄 ③ 학생용 응답은 미리 만들어 둔 키 하나(`hq:pub`)라 1번 = Redis 명령 1개. 저장소가 잠깐 죽어도 CDN이 마지막 정상 응답을 10분까지 보여 줌 |
| 확인 간격 | 퀴즈 탭을 보고 있을 때만: 대기 4초 · 진행 15초 · 마감 20초 · 숨김 30초 (사람마다 ±25% 어긋나게) |
| 문제 그림 | 내용 해시 주소 + 1년 캐시 (한 번 받으면 다시 안 받음), 업로드 때 휴대폰이 자동으로 줄임 |
| 제출 | 다 푼 뒤 한 번만 · 학번당 첫 제출만 저장(`HSETNX`) · 서버가 채점 |
| 학생 휴대폰 | 답을 푸는 즉시 휴대폰에 저장(새로고침·앱 종료에도 유지) · 제출 실패 시 2→4→8→15→30초 간격으로 자동 재전송 · 같은 접수 번호로 다시 보내도 중복 저장 안 됨 · 푸는 중에는 새 버전 자동 새로고침을 미룸 |
| 장애 자동 감지 | 퀴즈 서버에 3번 연속 연결이 안 되거나 제출이 3번 실패하면 학생 화면에 "연결이 불안정해요" + 예비 제출 버튼 + **휴대폰에 저장된 내 답 요약**(예비 제출에 옮겨 적기용). 서버가 돌아오면 저절로 사라짐 |
| 선생님 비상 스위치 | 기본 정보 → **퀴즈 예비 제출 안내 = 켜기** → 저장. 퀴즈 서버(Upstash)와 상관없는 `data.json` 경로라 Redis가 완전히 죽어도 작동. 연결이 안 되는 학생 휴대폰은 퀴즈 확인 때마다 이 설정도 같이 확인해서 1~3분 안에 반영 |

**예상 사용량 (350명, 퀴즈 30분 기준)**: Redis 명령은 학생 화면 조회가 인스턴스당 초당 1개 이하, 제출 350건 × 4개 = 1,400개 → 합쳐도 수천~수만 개로, Upstash 무료 한도(월 50만 개, 초당 1만 개)에 여유가 큽니다. 버셀 함수 호출도 무료 한도(월 100만 회) 안이에요. 그래도 행사 당일만큼은 Upstash 콘솔에서 **Pay as you go**(사용한 만큼, 10만 명령당 약 0.2달러)로 바꿔 두면 한도 초과 걱정이 없습니다.

### 행사 전 점검 (D-3까지)
0. **서버 점검 버튼**: 선생님 수정 → 퀴즈 카드 → **서버 점검**. "저장소 정상"과 "CDN 캐시 작동(HIT)"이 나오면 OK. CDN이 계속 MISS여도 ②·③ 방어 덕분에 버티지만, 그때는 아래 부하 테스트를 꼭 해 보세요. 행사 당일 시작 직전에도 한 번 눌러 보세요.
1. **부하 테스트**: 테스트 문제를 저장 → 새 회차 → ▶ 시작을 눌러 둔 뒤 PC에서 `node tools/quiz-loadtest.js https://내사이트.vercel.app 관리자비밀번호` (Node 18 이상). 350건이 모두 성공하고 95% 응답이 2초 이하이면 통과. 끝나면 ■ 마감 → **새 회차**로 가짜 제출을 비웁니다. (학교 와이파이처럼 한 곳에서 몰아서 보내는 테스트이므로 실제보다 가혹한 편이에요)
2. **구글 설문 예비본**: 같은 문제 + 학번·이름을 넣은 구글 설문(퀴즈 모드)을 만들고 주소를 수정 화면 **기본 정보 → 퀴즈 예비 제출 주소**에 저장해 두세요. 퀴즈 서버가 안 될 때 학생 화면에 "예비 제출 열기" 버튼이 뜹니다. QR을 발표 자료 마지막 장에도 넣어 두면 좋아요.
3. **연습 회차**: 아침 집결이나 이동 중에 2문제짜리 연습 퀴즈를 한 번 돌리고 **새 회차**를 만드세요. 학생들이 퀴즈 탭 열기·학번 입력·제출을 미리 해 보고, 학번·이름은 휴대폰에 남아 본 퀴즈에서 다시 안 적어도 됩니다.
4. 문제는 **큰 화면(PPT)에도 함께** 띄워 두세요. 휴대폰에 늦게 떠도 진행할 수 있어요.

| 상황 | 대처 |
|---|---|
| 일부 학생만 제출이 늦음 | 앱이 자동으로 다시 보내요. 마감을 1~2분 늦게 누르고, 공지로 "화면을 닫지 말고 기다려요" 안내 |
| 일부 학생만 "연결이 불안정해요" | 대부분 그 학생의 통신 문제예요. 와이파이↔데이터를 바꿔 보게 하고, 답은 휴대폰에 남아 있으니 기다리게 하기 |
| 문제가 안 뜸 / 서버 오류 / 퀴즈 카드에 오류 | ① 큰 화면 문제로 계속 진행 ② **기본 정보 → 퀴즈 예비 제출 안내 = 켜기 → 저장** ③ 큰 화면에 구글 설문 QR, "선생님 공지"로도 안내(공지는 퀴즈 서버와 별개라 작동). 학생 화면에 저장된 답 요약이 보이니 옮겨 적으면 돼요. 서버가 돌아오면 휴대폰에 남은 답이 자동으로 제출되므로, 시상은 두 결과를 합쳐서 판단 |
| Upstash 한도 초과 (콘솔에 limit exceeded) | Upstash 콘솔에서 Pay as you go로 바꾸면 바로 풀려요. 그동안 학생 휴대폰은 계속 재시도 |
| 진행 중 결과가 걱정될 때 | 마감 직후 **결과 불러오기 → CSV 내려받기**를 먼저 해서 컴퓨터에 보관 |
| 행사장 통신이 아예 안 됨 | 답은 휴대폰에 남아 통신이 되면 자동 제출되지만 시간 순위는 공정하지 않아요. **만점자 중 추첨** 등 시상 방식을 미리 정해 두세요 |
| 마감 뒤에 제출하지 못한 학생 | 접수 번호가 없으면 제출되지 않은 것이에요. 예비 제출 또는 담임 확인 |
| 같은 학번이 두 번 제출 | 첫 제출만 인정, 결과 화면 아래에 시도 기록이 나와요. 학번을 잘못 쓴 학생은 담임 선생님이 확인 |

순위의 한계: 문제가 열리는 순간은 휴대폰마다 1초 안팎으로 차이가 날 수 있고, 통신 때문에 늦게 도착한 제출은 불리해요. 결과표의 "폰 측정"(문제를 본 뒤 제출까지)과 "재시도" 칸을 동점 근처 판단에 참고하세요.

개인정보: 학번·이름은 수상자 확인용이에요. 행사가 끝나면 CSV를 보관한 뒤 Upstash 콘솔에서 데이터베이스를 삭제하세요.

## 행사 전 꼭 할 일

1. **지도 탭에서 핀 위치 확인하기.** 집결 장소가 정문이 아니면 수정 화면에서 2번 위치를 다시 찍어 주세요.
2. **출발 전에 학생들이 한 번씩 접속하게 하기** (학교 와이파이나 버스 안). 서비스 워커가 화면과 지도를 저장해 두면 행사장에서 통신이 몰려도 열립니다. "홈 화면에 추가"를 안내하면 앱처럼 바로 열 수 있습니다.
3. 행사 당일 아침 이후 큰 수정을 하면 학생 휴대폰에 반영되는 데 몇 분 걸립니다. 식순 변경은 가능하면 전날까지 마쳐 주세요.

## 개발자 메모

- 화면 코드를 바꿔 다시 배포할 때는 `sw.js`의 `VERSION` 숫자를 올려 주세요. (데이터만 바꿀 때는 필요 없음)
- 연락처 등 `data.json` 내용은 누구나 볼 수 있습니다. 개인 휴대폰 번호 공개 여부는 학교 방침에 맞춰 정해 주세요.
